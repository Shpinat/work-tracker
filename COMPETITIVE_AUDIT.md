> **Дата аудита:** 27 октября 2026 г.
> **Роль:** Senior Product Analyst, UX/UI Designer & Frontend Architect
> **Объект анализа:** [WorkTrack](https://github.com/Shpinat/work-tracker) (локальная рабочая копия)

> **Целевая платформа:** Автономное Progressive Web App (PWA), статический хостинг GitHub Pages, 100% Offline-First.

## 1. Краткий вывод: текущее состояние WorkTrack

**WorkTrack** представляет собой зрелое, чистое и высокопроизводительное одностраничное веб-приложение (SPA/PWA), разработанное на чистом JavaScript (ES Modules) без внешних фреймворков, сборщиков и транспайлеров.

### Сильные фундаментальные качества:
1. **Абсолютная автономность (Offline-First):** приложение не имеет серверного бэкенда, не требует регистрации, учетных записей, API-ключей и внешних библиотек. Все ресурсы (JS, CSS, HTML, шрифты, SVG-иконки, манифест) кэшируются через [sw.js](file:///d:/Projects/work-tracker/sw.js) и хранятся на устройстве пользователя.
2. **Нулевая зависимость от внешних сервисов:** в проекте нет сторонних CDN, трекеров аналитики или сторонних шрифтов. Шрифтовой стек использует нативные системные шрифты (`system-ui`, `-apple-system`, `Roboto`, `"Segoe UI"`).
3. **Модульная доменная архитектура:** логика четко разграничена по каталогам `domain/` (расчеты зарплаты [payroll.js](file:///d:/Projects/work-tracker/domain/payroll.js), аналитика [analytics.js](file:///d:/Projects/work-tracker/domain/analytics.js), циклические графики [schedule.js](file:///d:/Projects/work-tracker/domain/schedule.js)), `data/` (хранилище [storage.js](file:///d:/Projects/work-tracker/data/storage.js), экспорт/бэкап [backup.js](file:///d:/Projects/work-tracker/data/backup.js)) и `ui/` (календарь, модальные окна, списки смен, тосты, иконки).
4. **Высокая скорость работы и UX:** интерфейс отзывчив, поддерживает тактильный отклик (Haptic Feedback через `navigator.vibrate`), свайпы переключения месяцев и жесты закрытия шторки на мобильных (Bottom Sheet).

### Выявленные слабые места и зоны риска:
1. **Хранилище с ключом по дате `YYYY-MM-DD`:** структура `shifts[dateKey]` допускает только одну смену в календарные сутки. Пользователь не может зафиксировать две раздельные смены в один день (например, утренняя и вечерняя подработка).
2. **Небезопасное восстановление резервной копии ([app.js#L1062](file:///d:/Projects/work-tracker/app.js#L1062-L1084)):** при выборе JSON-файла приложение мгновенно затирает текущие смены и настройки без предварительного предпросмотра метаданных (дата бэкапа, число смен) и без обязательного подтверждения пользователем.
3. **Отсутствие Web Share API для резервной копии ([data/backup.js#L27](file:///d:/Projects/work-tracker/data/backup.js#L27-L41)):** в то время как экспорт CSV поддерживает нативную отправку через меню «Поделиться», JSON-бэкап использует только скачивание через скрытый тег `<a>`, что неудобно на iOS и некоторых версиях Android.
4. **Смешение уже заработанного и планируемого заработка:** на карточке дохода отображается общая сумма всех смен месяца. Нет наглядного разделения на «Фактически отработано на сегодня» и «Ожидается по графику до конца месяца/периода».
5. **Отсутствие ночных надбавок и учета сверхурочных:** расчет ведется по плоской ставке (почасовой или фиксированной) плюс ручной бонус. Автоматического выделения ночных часов (например, с 22:00 до 06:00 с коэффициентом +20% по ТК РФ) или переработок сверх нормы нет.

### 2.2. Хранение данных и многопоточность
- **Механизм:** `window.localStorage`.
- **Ключи:** `my_work_shifts_v1` (объект смен), `my_work_settings_v1` (объект настроек), `my_work_theme_v1` (тема).
- **Поведение при перезагрузке:** данные загружаются синхронно при инициализации (`loadShifts()`, `loadSettings()`).
- **Поведение при открытии в нескольких вкладках:** при сохранении смены в [app.js#L546](file:///d:/Projects/work-tracker/app.js#L546) вызывается `shifts = loadShifts()` для минимизации конфликта, однако отсутствует глобальный обработчик `window.addEventListener("storage", ...)`, поэтому открытая вторая вкладка не обновляет календарь реактивно при изменении данных в первой.
- **Ошибки хранилища:** операции обернуты в `try / catch` ([data/storage.js#L106-L127](file:///d:/Projects/work-tracker/data/storage.js#L106-L127)), однако при `QuotaExceededError` пользователь получает лишь булевый `false` без диалога очистки или предупреждения о нехватке места.

### 2.3. Расчет рабочего времени и смен
- **Расчет длительности ([domain/payroll.js#L25](file:///d:/Projects/work-tracker/domain/payroll.js#L25-L36)):**
  Функция `calcHoursDiff(start, end, breakMins)` корректно обрабатывает переход через полночь: если `endMins < startMins`, к конечному времени добавляется `1440` минут (`24 * 60`). Перерыв вычитается из общего времени с ограничением `Math.max(0, netMins)`.
- **Оплата ([domain/payroll.js#L46](file:///d:/Projects/work-tracker/domain/payroll.js#L46-L52)):**
  Поддерживает два режима: `hourly` (часы × ставка + бонус) и `fixed` (ставка за смену + бонус).
- **Разделение выплат (Аванс и Расчет):**
  Настраиваемый день отсечки (`advanceCutoffDay`, по умолчанию 15-е число). Смены с 1-го по `cutoffDay` относятся к авансу, остальные — к расчету.
- **Финансовая цель («Копилка»):**
  Индикатор выполнения плана на месяц с расчетом процента и количества оставшихся смен для закрытия цели.
- **Кастомизация пресетов:**
  Три полностью настраиваемых шаблона смен (название, интервал времени, перерыв).

### 5.2. Детальный UX/UI аудит элементов

#### 1. Карточки ключевых показателей (Hero Cards)
- **CalculatorAI:** выделяет ближайшую выплату («Зарплата через 2 дня») и делит доход на «Уже заработано» и «Ожидается по графику». Числа крупные, с указанием периода начислений.
- **WorkTrack ([index.html#L116-L129](file:///d:/Projects/work-tracker/index.html#L116-L129)):** три равные карточки (`Смен`, `Часов`, `Доход`). Они компактны, отлично помещаются в одну строку на мобильном экране, но не информируют о приближении дня выплаты и не делят месяц на отработанную и планируемую части.
- *Рекомендация для WorkTrack:* сохранить компактную сетку 3 карточек, но внутри карточки «Доход» или в блоке аванса/зарплаты выводить подсказку: сколько уже отработано на сегодняшнюю дату.

#### 2. Таймер текущей смены
- **CalculatorAI:** крупный заметный виджет с кнопкой «Начать смену», индикатором секунд и растущей суммой оплаты.
- **WorkTrack:** отсутствует. Чтобы записать смену, нужно найти день в календаре, нажать на него и сохранить модалку.
- *Рекомендация для WorkTrack:* добавить компактную кнопку/плашку в верхней части главного экрана «Начать смену». При активности она показывает секундомер и накопленный заработок, а по клику на «Завершить» сразу открывает `#shiftModal` с подставленным временем.

#### 3. Модальные окна и формы

## 6. Сильные стороны WorkTrack, которые нельзя ухудшать

1. **Мгновенный запуск и легковесность:** общий вес всех файлов приложения (HTML, CSS, JS, иконки) составляет менее **200 КБ**! Приложение открывается за доли секунды даже на старых смартфонах.
2. **Нулевой порог входа:** пользователю не нужно подтверждать почту, придумывать пароли, принимать условия о куки и давать согласия на обработку персональных данных.
3. **Прямое взаимодействие с календарем:** визуальный календарь на главном экране — идеальный инструмент для тех, кто мыслит датами и сменами, а не абстрактными списками.
4. **Нативный мобильный опыт (Bottom Sheet + Haptic):** жесты смахивания модальных окон, вибрация при нажатии кнопок, адаптивные сегментированные переключатели (Segmented Controls) создают ощущение нативного iOS/Android приложения.

6. **Полная безопасность данных от утечек:** данные физически не могут утечь в сеть, потому что приложение не отправляет ни единого сетевого запроса наружу.

## 7. Недостающие функции и возможности для развития

### 7.1. Автономный таймер смены («Приход / Уход»)
- **Идея:** кнопка «Начать смену» на главном экране или в шапке.
- **Автономная реализация:** состояние таймера хранится в `localStorage` (`{ running: true, startedAt: ISOString, preset: 'day' }`). При загрузке страницы таймер восстанавливается. Секундомер тикает локально через `requestAnimationFrame` или `setInterval`. Кнопка «Завершить» останавливает отсчет и открывает окно смены с подставленным временем прихода и ухода.

### 7.2. Разделение дохода на «Факт» и «Прогноз»
- **Идея:** в текущем месяце рассчитывать две суммы:
  - `earnedToDate`: сумма смен, дата которых $\le$ сегодняшнему числу.
  - `projectedRemaining`: сумма смен по графику, дата которых $>$ сегодня.
  - `totalProjected`: факт + прогноз.
- **Польза:** в середине месяца пользователь сразу видит: «Заработано на сегодня: 42 000 ₽ • Ожидается до конца месяца: 38 000 ₽ • Итого: 80 000 ₽».

### 7.3. Сверка расчётного листка (Калькулятор расхождений)
- **Идея:** автономный инструмент в разделе аналитики или списка смен.
- **Автономная реализация:** пользователь выбирает месяц, вводит начисленную в бухгалтерии сумму. Приложение сопоставляет её с суммой по записанным сменам, выводит разницу (`+` переплата или `-` недоплата) и детализирует возможные причины (неучтенный бонус, разница в часах, округление).

### 7.4. Поддержка ночных надбавок
- **Идея:** в настройках пресета добавить процент ночной доплаты (например, `20%`) и интервал ночного времени (по умолчанию с `22:00` до `06:00`).
- **Автономная реализация:** функция `calcShiftPay` рассчитывает пересечение интервала смены с ночным окном и автоматически начисляет надбавку на ночные часы.

### 7.5. Расширение библиотеки стандартных графиков
- **Идея:** добавить в [domain/schedule.js](file:///d:/Projects/work-tracker/domain/schedule.js) популярные шаблоны:
  - «Сутки через трое» (1 смена 24ч / 3 вых)
  - «4 через 4» (4 день / 4 вых)
  - «2-2-3 (Питман)» (чередующийся 14-дневный цикл)

## 8. Риски и ограничения автономной PWA на GitHub Pages

### 8.1. Изоляция и ограничения хранилища
1. **Очистка данных браузером (Storage Eviction):** на iOS Safari, если веб-приложение не установлено на экран «Домой» и к нему не обращались более 7 дней, Safari может очистить `localStorage`.
   *Решение:* запросить постоянное хранилище через `navigator.storage.persist()` при инициализации приложения и сделать регулярное резервное копирование максимально удобным.
2. **Лимит объема `localStorage`:** составляет 5 МБ на домен. Для текстовых данных смен (около 150 байт на смену) этого объема хватает более чем на 30 000 смен (около 80 лет непрерывной работы), то есть переполнение маловероятно, если не сохранять фотографии или тяжелые вложения.

### 8.2. Обновление Service Worker на GitHub Pages
1. **Подкаталог репозитория:** на GitHub Pages приложение обычно публикуется по пути `https://<username>.github.io/<repo>/`. Все пути в [sw.js](file:///d:/Projects/work-tracker/sw.js) и [manifest.webmanifest](file:///d:/Projects/work-tracker/manifest.webmanifest) обязаны оставаться **относительными** (`./index.html`, `./style.css`), иначе при абсолютных путях (`/index.html`) произойдет ошибка 404. В WorkTrack это требование уже соблюдено.
2. **Застревание старого кэша:** если Service Worker использует стратегию Cache-First без уведомления пользователя, обновленный код может не примениться. В WorkTrack используется стратегия Network-First с фоллбэком в кэш ([sw.js#L53](file:///d:/Projects/work-tracker/sw.js#L53)), что обеспечивает мгновенную загрузку свежего кода при наличии сети.
   *Улучшение:* добавить всплывающий баннер «Доступна новая версия WorkTrack» при событии Service Worker `updatefound` и кнопку «Обновить» (`skipWaiting`).

## 9. Спецификация механизма резервного копирования (Backup Spec)

С учетом строгих требований к надежности и пользовательской инициативе, текущая реализация в [data/backup.js](file:///d:/Projects/work-tracker/data/backup.js) и [app.js](file:///d:/Projects/work-tracker/app.js) требует доработки до следующей строгой спецификации.

### 9.1. Структура JSON-файла резервной копии (Схема v2)
```json

      "night": { "name": "2-я смена", "start": "14:00", "end": "20:00", "breakMins": 0 },

```

### 9.2. Создание и передача резервной копии
1. Пользователь нажимает в настройках кнопку **«Создать резервную копию»**.
2. Приложение собирает актуальные объекты `shifts` и `settings`, вычисляет статистику `stats` и формирует валидный JSON.
3. Формируется имя файла: `worktrack_backup_YYYY-MM-DD.json`.
4. Создается `File` объект с MIME-типом `application/json`.
5. **Проверка Web Share API:**
   ```javascript
   if (navigator.canShare && navigator.canShare({ files: [backupFile] })) {
     await navigator.share({
       title: "Резервная копия WorkTrack",
       text: `Резервная копия смен (${shiftsCount} смен) от ${dateStr}`,
       files: [backupFile],
     });
   } else {
     // Фоллбэк: стандартное скачивание браузером
     triggerDownload(blob, filename);
   }
   ```
6. Выводится тост: `Резервная копия успешно создана`.

### 9.3. Безопасное восстановление (Восстановление с предпросмотром)
1. Пользователь нажимает **«Восстановить из файла»**.
2. Открывается нативный системный диалог выбора файла (`accept=".json,application/json"`).
3. При выборе файла приложение **не перезаписывает данные сразу**, а выполняет валидацию:
   - Проверка синтаксиса JSON.
   - Проверка сигнатуры приложения (`payload.app === "WorkTrack" || payload.app === "work-tracker"`).
   - Поддержка обратной совместимости (если `schemaVersion` отсутствует, обрабатывать по правилам схемы v1).
   - Подсчет количества смен в файле и диапазона дат.
4. Открывается модальное окно предпросмотра:
   - **Заголовок:** «Восстановление данных»
   - **Сведения о бэкапе:**
     - Дата создания: `27.10.2026 18:30`
     - Количество смен: `142` (с 15.01.2025 по 26.10.2026)
     - Базовая ставка: `350 ₽/час`
   - **Предупреждение:** *«Внимание: текущие данные (118 смен) будут полностью заменены данными из файла. Это действие необратимо.»*
   - **Кнопка «Создать резервную копию текущих данных»** (для безопасного отката перед заменой).
   - **Кнопки:** `[Отмена]` и `[Заменить и восстановить]` (акцентная красная/предупреждающая).
5. Только после явного клика на `[Заменить и восстановить]` данные валидируются через `sanitizeSettings`, сохраняются в `localStorage`, обновляется интерфейс и выводится сообщение об успехе.
6. В случае ошибки парсинга текущие данные остаются в полной сохранности, а пользователю выводится понятная причина ошибки.

### 9.4. Разграничение JSON и CSV
- **JSON (.json):** техническая полная копия приложения, предназначенная исключительно для переноса состояния между устройствами или восстановления после очистки браузера. Содержит полную структуру настроек, пресетов и параметров.
- **CSV (.csv):** пользовательский отчет, оптимизированный для открытия в Microsoft Excel, Apple Numbers или Google Таблицах. Содержит человекочитаемые колонки, BOM-маркер UTF-8 (`\uFEFF`) и точку с запятой `;` в качестве разделителя для русскоязычной локали Excel. Не используется для восстановления приложения.
